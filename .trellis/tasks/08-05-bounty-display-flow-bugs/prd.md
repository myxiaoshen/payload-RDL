# 修复悬赏板块发起人匿名与流程展示问题

## Goal

修复悬赏列表/详情中发起人始终显示为「匿名」的问题；确保悬赏采纳/关闭后详情页状态正确更新；按明确的产品规则展示参与者、采纳结果与驳回原因。

## Background / Confirmed Facts

来自当前代码与仓库证据（非产品决策）：

1. **发起人显示「匿名」根因明确**
   - `users` 集合 `read: authenticated`，未登录不可读用户资料。
   - 悬赏列表与详情以 `depth: 1` 拉 `author`，但查询未传当前 user，关系展开失败。
   - UI 回退逻辑：`author` 非对象时显示「匿名」。
   - 帖子域已有先例：`populateAuthors` + `populatedAuthors` 公开安全字段。

2. **采纳/关闭后端会改状态**
   - `/api/bounty/accept`：`status: fulfilled`、`escrowReleased: true`、`acceptedSubmission`。
   - `/api/bounty/close`：`closed` 或管理员 `rejected`，并退币。
   - 前端采纳/关闭后均 `router.refresh()`。
   - 详情查询 where 已包含 `open | fulfilled | closed`。
   - 「详情状态不变」仍需在设计阶段定位缓存、查询上下文、字段 access 或筛选观感问题。

3. **参与者公开现状与需求表述不一致**
   - 当前详情仅发起人可读全部提交列表；路人看不到参与者头像、名单、采纳对象。
   - 提交列表目前只显示 submitterName 文本，无头像。
   - 无驳回原因字段：方案未采纳仅标 status；审核驳回仅改 bounty status。
   - 用户原述「所有人都能看到谁参加了、头像、采纳了谁、为什么驳回」更像期望行为，需产品确认可见范围。

## Requirements

### R1. 发起人身份展示（明确 bug）

- 悬赏列表与详情应展示发起人公开显示名（优先 name）。
- 未登录访客也应能看到发起人公开显示名。
- 显示名回退（已确认 Y）：`name` → 否则 `用户{id}` → 再否则不显示为固定「匿名」占位仅当完全无法解析 id。
- 公开展示**不使用 email**（含本地部分），避免隐私泄露。
- 不得因此放开 `users` 全字段公开读取。

### R2. 完成后详情状态同步（明确 bug）

- 采纳成功后详情状态为「已完成 / fulfilled」。
- 关闭成功后详情状态为「已关闭 / closed」。
- 已完成后不可再次采纳；关闭按钮不再出现。

### R3. 参与与结果展示（已确认：A 全员公开）

- **已确认可见范围：A. 全员公开**
  - 任意访客（含未登录）可见：参与者公开资料（显示名 + 头像）、谁被采纳、驳回/未采纳相关说明（若存在）。
  - 仍不公开：方案下载直链、邮箱、余额等隐私字段。
- 前台详情页应对所有人渲染参与/结果区（不再仅限发起人可见名单）。
- 发起人仍独有操作权：采纳、关闭、下载已采纳方案。
- **驳回/未采纳说明（已确认：仅系统文案，不做自由文本）**
  - 方案 `accepted`：展示「已采纳」。
  - 方案 `rejected`（因其他方案被采纳）：展示固定系统文案，例如「未采纳 / 已选择其他方案」。
  - 方案 `submitted`（进行中）：展示「待处理」或等价文案。
  - 悬赏审核驳回（`pending → rejected`）：本任务不对公开展示手写原因；公开详情本就不包含 `pending/rejected` 状态（现有查询仅 `open|fulfilled|closed`）。作者侧仍可通过个人中心看到「已驳回」状态标签。
  - **本任务不新增**审核驳回原因字段、方案拒绝原因字段或相关表单。

### R4. 安全与权限约束

- 方案下载地址仍不得对非授权用户暴露。
- 参与者公开信息仅限显示名、头像等展示字段。
- 不通过放宽 `users.read = anyone` 作为捷径。

## Out of Scope（暂定）

- 市场资源作者匿名的同类问题（可另开任务）。
- 悬赏发布/提交/支付主流程大改。
- 管理后台审核 UI 大改。
- 推送文案全面重写。

## Acceptance Criteria

- [ ] 未登录访问悬赏列表与详情时，发起人不再固定显示「匿名」（有 name 的用户显示 name）。
- [ ] 登录访客同样能正确看到发起人显示名；发起人本人/管理员身份判断仍正确。
- [ ] 采纳成功后刷新详情，状态为「已完成」，不可再次采纳。
- [ ] 关闭成功后刷新详情，状态为「已关闭」。
- [ ] 参与者/采纳/驳回信息的可见范围符合已确认的 R3 策略；下载直链仍不泄露。
- [ ] 参与结果区使用系统文案区分已采纳 / 未采纳 / 待处理；不出现自由文本驳回原因字段。
- [ ] 相关前台路径与 API 不引入 users 隐私字段公开可读。

## Decisions

- **R3 可见范围 = A 全员公开**（2026-08-05）：访客可见参与者显示名/头像、采纳结果；下载与隐私字段仍保护。
- **驳回说明 = 仅系统文案**（2026-08-05）：不做自由文本原因；方案未采纳用固定文案；不新增原因字段/表单。
- **显示名回退 = Y**（2026-08-05）：`name` → `用户{id}`；公开不暴露 email。
